## Bugs found live (both now regression-tested)

1. **FK flush-ordering (SQLAlchemy autoflush).** Interleaving `session.get()` queries
   with pending child inserts let query-invoked autoflush write `pokemon_types` before
   its `types` stub row → `ForeignKeyViolation` on PostgreSQL. Invisible in unit tests:
   SQLite doesn't enforce FKs by default. Fix: two-phase normalizer (stubs + `flush()`,
   then children). Regression test runs the normalizers against real pg
   (`test_normalize_integration.py`).
2. **Alembic URL precedence.** `env.py` preferred `DATABASE_URL` env over the
   programmatic `sqlalchemy.url`, so scratch-DB migrations in tests silently targeted
   the wrong database. Fix: explicit config wins; env var is the fallback.

Also hardened: the entity backfill now tolerates per-resource upstream failures —
PokéAPI served a persistent 502 for `/move/436` (charge-beam) all evening (verified
manually: 435/437 → 200, 436 → 502). The run completes, reports the failure, and the
next run retries it because no snapshot gets written. Regression test included.

## Surprises / lessons

- SQLite-only unit tests give false confidence about FK correctness — the pg
  integration layer earns its keep.
- Real external APIs break in boring ways (one 502 resource); bulk jobs need per-item
  failure isolation, not just retries.
