# 0004 — 2026-08-05 — 0.4: Local dev environment

## What was done

- `docker-compose.yml`: `pgvector/pgvector:0.8.0-pg16` (pinned), healthcheck with
  `pg_isready`, named volume, credentials from `.env` with dev defaults.
- `.env.example` with every key grouped by consumer (Postgres, GCP/ADC, embeddings,
  Langfuse) and a real `.env` created locally (never committed).
- `Makefile`: `up/down/ps/logs/lint/format/test/check`, iterating over a `COMPONENTS`
  list that grows as components land.

## Why

One-command local stack and one-command quality gate, before any component that needs a
database exists.

## How it was tested

- `docker compose up -d` → container healthy.
- Live verification inside the container: `CREATE EXTENSION vector` → 0.8.0, and a real
  `CREATE INDEX ... USING hnsw (embedding vector_cosine_ops)` on a `vector(768)` column
  succeeded — the pinned image supports our exact index plan (risk #5 from the plan,
  closed).
- `make check` from Git Bash: ruff + 18 tests green.

## Cost

$0.

## Surprises / lessons

- `bash` from PowerShell resolves to WSL (HOME=/home/jeron, no poetry) — NOT Git Bash.
  Make targets must be run from real Git Bash (`C:\Program Files\Git\bin\bash.exe`),
  where make (WinGet), poetry and docker are all on PATH.
- Windows-style `$(HOME)` (`C:\...`) corrupts PATH inside make recipes because of the
  drive colon; kept a POSIX-safe PATH export line which is a no-op where PATH is fine.
