## Two API prerequisites this phase forced

- **CORS allowlist** (the gap the 6.6 runbook flagged). `CORS_ALLOWED_ORIGINS` is an
  explicit list; a literal `*` is *stripped*, not honored, so the guideline against a
  production wildcard is enforced by code rather than by discipline. CORS is registered
  OUTERMOST so even a 401 from the API-key gate carries the headers a browser needs to
  read the rejection instead of reporting an opaque network error.
- **`GET /pokemon/{id}/sprite`** — the UI had no legitimate way to show images. The
  phase's definition of done says the UI consumes ONLY the public API, so hotlinking
  PokéAPI's raw GitHub URLs was out; serving from `DATA_DIR` is the API's job. Includes
  a `is_relative_to(data_dir)` guard: `local_path` comes from our own ingest, but a
  poisoned value would otherwise make this an arbitrary-file reader.

## The UI

Next.js App Router, **static export** (`output: 'export'`) — no server runtime, no
Dockerfile, per the guideline that frontends ship as static. 156 pages build: search,
chat, compare, not-found, plus one pre-rendered page per ingested Pokémon
(`generateStaticParams` over a configurable id range, default 151 — the ingested
generation). Each page is a shell that fetches in the browser, so the build makes zero
API calls.

- `src/lib/api.ts` is the only module that talks HTTP. It translates FastAPI's two
  `detail` shapes (string and 422 list) into one message, and turns a failed fetch into
  "Cannot reach the API at … Is it running?" rather than leaking `TypeError: Failed to
  fetch`.
- `/` — text search with mode and **embedding-space** selectors (the 6.1 local space is
  selectable), plus an image drop-zone.
- `/pokemon/{id}/` — card, stats, abilities, evolution chain. The chain is supporting
  detail, so its failure degrades to a note instead of blanking the page.
- `/chat/` — surfaces everything the pipeline reports: citations, abstention,
  per-warning notices, and the corrections counter. Hiding those would misrepresent a
  system whose whole point is that it says when it does not know.
- `/compare/` — both candidates with judge verdict, the **self-graded** caveat rendered
  explicitly, and latency/token counts. Lists the shared `context_document_ids` so a
  viewer can verify the comparison was fair rather than take it on trust.
- The IP disclaimer lives in the root layout — structurally impossible to ship a page
  without it.

## How it was tested

**Unit, offline (28 tests):** the vitest setup replaces `fetch` with a stub that
*throws*, so an un-faked call fails loudly instead of reaching the network. Covers the
client's URL shapes and error translation, and every page against fakes — including
abstention/warnings/corrections rendering, the self-graded badge, the shared-context
proof, and a card surviving a failed evolution-chain call.

**API: 128 passed** (16 new: sprite endpoint + CORS). `pnpm typecheck`, `oxlint` and
`prettier --check` clean; `pnpm build` produces the 156-page export.

**Live, in a real browser** against the real stack (API on 8002, Postgres in Docker,
ingested Gen-1 corpus):

- Search *"which pokemon has a plant bulb on its back"* → Bulbasaur ranked 1st,
  10 hybrid results, space label echoed.
- `/pokemon/1/` → card, stats, abilities, full Bulbasaur→Ivysaur→Venusaur chain, sprite
  loaded from the API (`GET /pokemon/1/sprite` → 200).
- `/chat/` *"what type is Gengar?"* → "Gengar is a Ghost/Poison type Pokémon [1]" with
  the citation resolved to the Gengar card.
- `/compare/` *"how does Charmander evolve?"* → both providers answered and were judged;
  the self-graded caveat rendered; vertex 3195 ms / 269 output tokens vs ai-studio
  632 ms / 30. Consistent with the 6.2 report's finding.
- `/search/image` with the real Pikachu sprite → pikachu #25 at score 1.0000.
- Zero browser console errors.

## Surprises / lessons

- **`user.upload` respects the input's `accept` attribute**, so the "rejects a wrong
  file type" test never fired the handler. Correct behaviour by testing-library — and it
  exposed that the local validation matters for the path that genuinely bypasses
  `accept`: **drag-and-drop**. Rewrote the test to fire a real drop event, which is what
  it should have exercised all along.
- **Three dependency-version traps in one install.** `eslint@9.42.0` doesn't exist
  (I pinned a guessed version); TypeScript 5.9.4 doesn't exist (5.9.3 does); and the
  machine's `minimumReleaseAge=1440` supply-chain policy **failed closed** on
  `eslint-config-next` and `typescript` because pnpm's cached ABBREVIATED registry
  metadata omits the `time` field it needs. Fixes, in order of principle: query the
  registry instead of guessing versions; switch to **oxlint** (explicitly allowed by the
  guidelines) rather than fight `eslint-config-next`; and clear the abbreviated metadata
  cache so pnpm refetches full documents — which makes the age check *run* rather than
  disabling the protection. Never weaken a security setting to make an install pass.
- **Prettier reads `.editorconfig`**, which set `indent_size = 4` globally for Python.
  Rather than override it in `.prettierrc`, added a `[*.{ts,tsx,...}]` section with 2 —
  one source of truth for indentation, both toolchains obeying it.
- The `role="button"` div for the drop-zone was flagged by oxlint's a11y rules; making
  it a real `<button>` deleted the hand-written keyboard handler and got focus and
  disabled semantics for free. The linter was right and the code got shorter.
