# 0012 — 2026-08-05 — 1.5: Snapshot normalizer

## What was done

- `pipeline/normalize.py`: one normalizer per resource type (`type`, `ability`, `move`,
  `pokemon-species`, `pokemon`, `evolution-chain`), exported in dependency-safe order.
- Strategy: entity rows merged by PokéAPI id; child collections (types/abilities/stats/
  moves/flavor texts/evolution edges) replaced wholesale — safe because snapshots are
  immutable, and guarantees convergence. Sprite manifest rows are get-or-create with
  URL refresh (downloader must notice changed URLs).
- Referenced entities inside a pokemon payload become stub rows (id+name) so FKs hold;
  full resource payloads enrich them later without being overwritten by stubs.
- Fail-fast: pokemon without its species raises `NormalizationError` with the fix in
  the message; unknown generation names and non-numeric reference URLs also fail fast.
- English flavor texts only for the MVP, deduped per (version, language), whitespace
  control characters cleaned.
- Committed trimmed-but-faithful fixtures: bulbasaur pokemon + species, evolution
  chain 1 (bulbasaur→ivysaur→venusaur), razor-leaf move, overgrow ability.

## Why

This is the boundary where raw external data becomes trusted domain rows — everything
downstream (documents, RAG facts validation in 5.4) reads these tables.

## How it was tested

7 new unit tests (20 total in the component, offline): URL id extraction, species row +
flavor filtering, full pokemon children (types slots, hidden abilities, stats, moves
collapsed across version groups, 3 sprite kinds), fail-fast without species, double-run
idempotence with exact row counts, evolution edges with levels/trigger/conditions JSON,
stub enrichment by full move/ability payloads.

## Cost

$0.

## Surprises / lessons

PokéAPI repeats a move per version group — collapsing to distinct (move, method, level)
was needed to keep the composite PK meaningful.
