# 0011 — 2026-08-05 — 1.4: Domain tables (migration 0002)

## What was done

- 12 domain models in `pokedex_db.models`, reusing PokéAPI ids as primary keys for
  traceability: `species` (incl. evolution_chain_id, legendary/mythical flags),
  `pokemon` (PokéAPI units kept: height dm / weight hg), `types`+`pokemon_types`
  (slot composite PK), `abilities`+`pokemon_abilities` (is_hidden),
  `pokemon_stats` (stat_name composite PK), `moves`+`pokemon_moves`
  (PK pokemon+move+learn_method+level), `evolutions` (edges from→to with trigger/
  min_level/item + verbatim `conditions` JSON, unique per edge), `flavor_texts`
  (unique species+version+language), `sprites` manifest (unique pokemon+kind,
  license note, sha256).
- Migration 0002 autogenerated against the live pg at 0001, then reviewed and cleaned.
  Plain strings instead of PG enums for damage_class/learn_method/kind — boring wins.
- Dev database upgraded to 0002; `pipeline status` now reports 13 empty tables.

## Why

The normalizer (1.5) needs a target schema; the API (1.9) reads these tables.

## How it was tested

libs/db integration suite (RUN_INTEGRATION=1): upgrade to head asserts all 13 tables
exist, downgrade to base removes them, re-upgrade idempotent — 5/5 green. Unit tests
unaffected (3 passed). ruff clean.
