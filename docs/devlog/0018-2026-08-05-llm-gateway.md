# 0018 — 2026-08-05 — 3.1: LLM gateway (provider independence)

## What was done

- `libs/llm-gateway` (`pokedex_llm`): `LLMGateway` Protocol (`generate`/`stream`,
  `Usage`, `GenerationRequest/Result`); error taxonomy AS PART OF THE CONTRACT —
  adapters translate every vendor failure into `TransientProviderError` (fallback
  material, raised only after the adapter's own bounded 429/5xx retries) or
  `PermanentProviderError` (fail fast). Vendor exceptions never escape.
- `VertexGeminiAdapter`: message-role mapping (system → system_instruction,
  assistant → model), temperature/max_tokens/response_mime_type passthrough, retries
  with logged backoff, usage extraction.
- `FakeLLM`: scripted responses + error injection + request recording; falls back to a
  default response for flow-only tests.
- **Shared contract-test suite** (`GatewayContract`): any adapter passes the same tests;
  FakeLLM runs it in CI, the Vertex adapter runs it under `RUN_LIVE=1 -m live`.

## Live findings (gemini-3.6-flash, ~$0.003 spent)

1. **Thinking tokens share `max_output_tokens`.** With a 64-token budget the reasoning
   phase can consume everything before any visible text is emitted → empty streams,
   non-deterministically. Fix: realistic budgets (contract uses 1024); Phase-3 prompts
   must set generous limits.
2. **Thought tokens are billed output.** `usage_metadata.thoughts_token_count` is
   separate from `candidates_token_count`; the adapter now reports
   `output_tokens = visible + thoughts` (breakdown in metadata) so Langfuse cost
   tracking will be honest.
3. Live contract 3/3 green after the fix (generate, stream, identity).
