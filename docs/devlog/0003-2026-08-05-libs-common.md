# 0003 — 2026-08-05 — 0.3: libs/common foundations

## What was done

- First Poetry component: `libs/common` (`pokedex_common`), Python pinned `>=3.13,<3.14`,
  `poetry.lock` committed.
- `BaseAppSettings.load()` — pydantic-settings base; fails fast at startup with an
  actionable message (which field, why, where to fix) via `SettingsError`.
- `configure_logging()` + `JsonFormatter` — one JSON line per event with
  timestamp/level/message/component/request_id; extras pass through; idempotent setup.
- `request_id` contextvar helpers (`new/set/get/reset`) — generated at the edge, read by
  the formatter.
- `contracts.py` — `RAGResponse` / `Citation` / `ResponseStatus` matching the API
  contract from the proposal (answered | corrected | insufficient_evidence |
  provider_error).

## Why

Every later component needs these four things; building them first means no component
ever hand-rolls config, logging or contract shapes.

## How it was tested

18 unit tests (`poetry run pytest`, all green, offline): settings load/fail-fast/invalid
values/defaults; formatter JSON shape, request-id inclusion, extras, exceptions,
idempotency; contextvar roundtrip; contract bounds (confidence 0..1, marker ≥ 1) and
status values. `ruff check` + `ruff format --check` clean. Locked versions: pydantic
2.13.4, pydantic-settings 2.14.2, pytest 8.4.2, ruff 0.16.1.
